# データを外へ運ぶ

[English](carrying-data-outward.md) · 日本語

amenbo のデータを端末の外へ運ぶプラグイン——ビューワ、監査、バックアップの自動化、他ツールへの
ミラー——が従う作法です。用途が違っても、運び方は同じにします。

この文書は、その運び方だけを扱います。プラグインそのものの書き方は
[プラグインを作る](writing-a-plugin.ja.md)にあります。

> 外へ運ぶ口は amenbo 11.0.0 から使えます。手元で `amenbo sync --help` が応えるか確かめてください。

## 一方通行・読み取り専用

外に置いたものを書き換えて本体へ戻す経路はありません。`sync` に書き込む口は無く、スナップショットを
読み戻すコマンドもありません。片方向に割り切ることで、衝突の解決が原理的に要らなくなります。

## 本体が出す4つの口

| 口 | 返すもの | いつ使うか |
| --- | --- | --- |
| `amenbo sync version` | 窓の版1つ | 送る前に「変わったか」を確かめる。**頻繁に呼ぶ** |
| `amenbo sync snapshot` | 窓の全レコードと、台帳の位置 | 初回・リセット・Gap のとき |
| `amenbo sync changes --since <cursor>` | 未読分の「どのレコードが変わったか」と、次のカーソル | 平常時 |
| `amenbo sync records --dataset <名> --ids <id,…>` | そのレコードの現在の値 | 変わったと言われたものを読み返すとき |

**訊くのは頻繁、運ぶのは稀。** 版を訊く口はスナップショットを組み立てずに答えるので、変わっていない
ことを確かめるために全量を作らせずに済みます。

```json
{ "project_id": 3, "version": 4821 }
```

**版は大小ではなく、同じかどうかで見ます。** `restore` はストアを巻き戻し、版もいっしょに戻るので、
小さくなったこともまた「変わった」です。この build が版を刻み始めてから何も書かれていない窓は `0` を
返します。

## 窓は、あなたが観測している範囲

返ってくるものはすべて、呼んだ側が読める窓に閉じています。1つのプロジェクトを観測するために起動された
プラグインには、そのプロジェクトだけが返ります。窓は `AMENBO_PLUGIN_REACH` で渡されるものと同じです。

版も窓ごとです。別のプロジェクトが動いても、あなたの版は動きません。

## カーソルはプラグインが持つ

本体は持ちません。どこまで読んだかを自分の設定として保存し、次に渡します。

最初のカーソルは `sync snapshot` のヘッダが名乗ります。

```json
{
  "amenbo_sync": {
    "format": "amenbo-sync-json",
    "format_version": 1,
    "schema_version": "1",
    "app_version": "11.0.0",
    "taken_at": "2026-08-09T09:00:00+00:00",
    "project_id": 3,
    "cursor": 4795
  },
  "tables": { "project": [], "task": [], "decision": [] }
}
```

スナップショットは**ひとつの瞬間**から読まれます。中にあるものが、中に無いものを指すことはありません。
つなぎのレコードは、両端が窓の中にあるときだけ乗ります。プラグインの secret は乗りません。添付は行だけが
乗り、**バイトは端末に残ります**。

## 平常時の流れ

1. `amenbo sync version` を訊く。保存した版と同じなら何もしない
2. `amenbo sync changes --since <保存したカーソル>` で未読分を取る
3. `insert` / `update` と言われたものを `amenbo sync records` で**読み返して**現在の値を得る
4. 外へ送る
5. 応答の `cursor` を保存する

台帳が返すのは「どのレコードが変わったか」だけで、**中身は入っていません**。

```json
{
  "v": 1,
  "project_id": 3,
  "cursor": 4821,
  "more": false,
  "changes": [
    { "dataset": "task", "op": "update", "record_id": 12 },
    { "dataset": "task", "op": "delete", "record_id": 15 }
  ]
}
```

**削除も届きます。** `op` が `delete` のものは読み返す先がもうありません。外の写しから消してください。
消し忘れると、amenbo で消したものが外に残り続けます。

1ページは有限です。切り詰めたときは `more` が立つので、受け取ったカーソルを持ってすぐ戻ってきます。

読み返しは、変更が名乗った `dataset` と `record_id` をそのまま渡します。

```sh
amenbo sync records --dataset task --ids 12,15,31
```

返るのはスナップショットと同じ文書に、その表が1つだけ入った形です。**スナップショットを読めるものは、
これも読めます。** 1回で読めるのは1ページ分（500件）までで、それを超えると切り詰めではなく拒否されるので、
ページごとに訊いてください。

窓の外の id は、返らないのではなく**そこに無い**だけです。削除済みの id も同じですが、`delete` が
どれかを既に言っているので、答えの歯抜けが驚きになることはありません。

## 全量を毎回取らない

運ぶ物はプロジェクトの成長に比例して育ちます。変わるたびに全体を読む形は、いつか必ず破綻します。
未読分だけを取れば、載るのは変わったぶんだけです。

全量を通るのは**初回・リセット・Gap のとき**だけです。

## Gap が返ったら全量へ落ちる

長く止まっているとカーソルは台帳の保持期間を割ります。そのとき本体は、何も変わっていないと読めてしまう
空のページではなく、**欠けている**と言います。

```json
{
  "error": {
    "code": "sync_gap",
    "message": "the ledger cannot say what changed since 1200 — that cursor is outside the stretch it still speaks for",
    "hint": "Take the window again with `amenbo sync snapshot` and read on from the cursor its header names."
  }
}
```

終了コードは非ゼロです。黙って飛ばさないでください。受け取ったら `sync snapshot` を取り直し、その
ヘッダが名乗るカーソルから読み進めます。

履歴そのものを目的とする用途（監査など）は、ここで欠落を記録できます。**黙って歯抜けを作らない**のが
この表明の意味です。

## 全量を取り直すコマンドを持つ

「これまで読んだ位置を捨てて、全量を取り直す」——外へ運ぶプラグインは、これをコマンドとして出します。

**回復手段が1つに揃います。** 版がずれた、鍵を変えた、置き場のデータが壊れた、原因が分からない——
どれも同じ操作で直ります。用途ごとに違う手順を作ると、利用者は「これはこう、あれはこう」と覚え直す
ことになります。

## 合図に正しさを負わせない

本体は変更があったことをフックとして撃ちます。ただし**撃ちっぱなしなので取りこぼしえます**。

**契機を3つ持ってください。**

- フックを受けたとき
- プラグインの起動時
- 一定間隔

どれが欠けても、最後には追いつく形にします。正しさを保証するのはフックではなく、版とカーソルです。

**まとめ送りは運ぶ側で作ります。** 100件の変更で100回送らないでください。同じ launch で何件が後ろに
控えているかは `AMENBO_PLUGIN_REACH_QUEUE_REMAINING` が言います。

## 暗号は運ぶ側の責務

本体は鍵を持たず、口が返すのは平文です。端末の外へ出すなら、**プラグインが暗号化します**。

ローカルのストアは平文のままでかまいません。信頼境界は端末に閉じており、端末上の保護は OS の全ディスク
暗号が担います。動くのは端末の外だけなので、暗号もそこにだけ掛けます。

鍵を置き場に渡さないでください。渡した時点で、暗号化した意味が無くなります。
